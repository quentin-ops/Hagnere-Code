# Dossier de travail — Audit SEO : que doit-il contenir ?

## 1. Fiche d’identité

- Slug : `audit-seo-que-contient-il`
- Statut actuel : publiable — validation éditoriale déléguée le 20 juillet 2026
- Requête principale : audit SEO que contient-il
- Variantes : contenu audit SEO, livrable audit SEO, exemple rapport audit SEO, audit SEO complet, comment vérifier un audit SEO
- Moment du parcours : commander, recevoir ou arbitrer un audit avant de financer les corrections
- Lecteur précis : dirigeant ou indépendant qui possède un site mais ne peut pas vérifier seul un rapport technique
- Situation déclenchante : trafic qui baisse, refonte envisagée, devis SEO, dette technique, stagnation des demandes ou changement de prestataire
- Décision principale après lecture : accepter le rapport, demander des preuves, réduire ou étendre le périmètre, puis autoriser seulement les actions recevables
- Niveau de connaissance au départ : connaît Search Console ou quelques mots du SEO sans savoir distinguer erreur d’outil, cause probable et priorité métier
- Questions indispensables : quel périmètre a été observé ; quelles données ont été vues ; quelle preuve soutient chaque recommandation ; qui exécute ; comment vérifier après correction
- Objections : un score d’outil suffirait ; un rapport long serait forcément complet ; toutes les erreurs auraient la même urgence ; le prestataire pourrait garantir l’indexation ou la position
- Action autonome : utiliser la fiche de réception visible pour contrôler cinq recommandations du rapport
- CTA possible : faire cadrer un audit ciblé ou complet, avec accès minimaux et livrables explicites
- Hors périmètre : prix détaillés, sélection d’agence, tutoriel exhaustif d’outils, plan de migration, garantie de positions, audit RGAA ou juridique complet
- Date de la recherche : 20 juillet 2026
- Responsable : Codex pour Hagnéré Code

La décision principale : **un audit SEO n’est recevable que si chaque priorité
relie un fait vérifiable, un périmètre, une conséquence plausible, une action,
un responsable et un contrôle après exécution.**

## 3. Intention et différenciation

L’intention de recherche est mixte : comprendre les éléments habituels d’un
audit, préparer un devis et juger si le rapport reçu est exploitable. La réponse
francophone dominante prend la forme d’une checklist technique ou d’une page de
vente. Cela laisse quatre besoins mal servis :

- distinguer un scan automatisé d’un diagnostic interprété ;
- rendre visibles les données absentes et la couverture réelle ;
- transformer les recommandations en tâches recevables ;
- fournir au dirigeant un protocole de contrôle après correction.

La proposition originale est donc une **fiche de réception à six preuves** :

1. fait observé et reproductible ;
2. périmètre et source de données ;
3. conséquence et niveau de confiance ;
4. action avec responsable et dépendances ;
5. critère d’acceptation ;
6. mesure différée et limite de conclusion.

Un score global est volontairement exclu. Cent avertissements de métadonnées ne
compensent pas une section stratégique inaccessible à l’exploration, et une URL
en erreur ne justifie pas toujours une intervention si elle est volontairement
retirée.

### Formulations interdites

- aucune garantie d’indexation, de position, de trafic, de demande ou de chiffre d’affaires ;
- aucune équivalence entre « erreur d’outil » et « priorité métier » ;
- aucun score de santé présenté comme mesure indépendante de Google ;
- aucun volume d’URL analysées si le périmètre, les exclusions et les limites du crawl ne sont pas fournis ;
- aucun « tous les backlinks toxiques doivent être désavoués » ;
- aucun « les Core Web Vitals suffisent pour gagner des positions » ;
- aucun « un sitemap indexe les pages » ;
- aucun « Search Console et Analytics doivent afficher les mêmes chiffres » ;
- aucun « données structurées valides = résultat enrichi garanti » ;
- aucun fichier ou balisage spécial présenté comme obligatoire pour les réponses IA de Google ;
- aucune conformité RGPD, cookies ou RGAA déclarée à partir du seul audit SEO ;
- aucun faux cas client, gain, délai ou résultat Hagnéré Code ;
- aucun nombre universel de jours ou de pages pour qualifier un audit de complet.

### Empreinte éditoriale

- Ouverture : un rapport de 83 pages qui ne permet d’autoriser aucune correction.
- Progression : réception d’un livrable, puis reconstruction de ce qui manque.
- Artefact signature : fiche de réception d’une recommandation, sans note globale.
- Rythme : réponses courtes, comparaisons, exemple fictif et critères de décision.
- Lexique traduit à la première occurrence : crawl, indexation, canonique, journaux serveur, données structurées, Core Web Vitals, backlinks, maillage.
- CTA unique : après la comparaison des trois périmètres.
- Conclusion : l’audit est terminé seulement quand une autre personne peut exécuter et vérifier le plan.

## 6. Livrable attendu dans le guide

Le tableau copiable doit contenir :

| Champ           | Question de réception                                        |
| --------------- | ------------------------------------------------------------ |
| Fait            | Que peut-on reproduire aujourd’hui ?                         |
| Périmètre       | Quelles URL, données, dates et configurations ont été vues ? |
| Conséquence     | Quel risque utilisateur ou métier est plausible ?            |
| Confiance       | Est-ce observé, probable, à tester ou inconnu ?              |
| Action          | Que faut-il changer, conserver ou mesurer ?                  |
| Responsable     | Qui décide, implémente et valide ?                           |
| Acceptation     | Quel test prouvera que la tâche est correctement exécutée ?  |
| Mesure différée | Quand et avec quel indicateur examinera-t-on l’effet ?       |
| Limite          | Que cette action ne permet-elle pas de conclure ?            |

Exemple fictif :

- mauvais constat : « 1 247 pages dupliquées, priorité haute » ;
- constat recevable : « le crawl du 20 juillet a rencontré 1 247 URL à
  paramètres accessibles depuis le filtre catalogue ; 312 renvoient un contenu
  très proche de la catégorie canonique ; les journaux serveur n’ont pas été
  fournis ; bloquer ou consolider seulement après test sur un modèle et contrôle
  des pages qui génèrent des ventes ».

## 7. Ressource et conversion

- Ressource séparée : non ; la fiche visible est copiable sans formulaire.
- Résultat autonome : le lecteur peut contrôler cinq recommandations et écrire les demandes de complément.
- Bon fit : site existant, décision à prendre, accès en lecture possibles, équipe capable d’exécuter ou de déléguer.
- Mauvais fit : recherche d’une garantie de rang, absence totale de données, besoin limité à une vérification d’URL ou demande de certification juridique/accessibilité.
- CTA : `/demarrer-un-projet`, intitulé « Faire cadrer le périmètre de mon audit ».
- Promesse commerciale : cadrer les accès, modules, livrables et critères de réception ; dire honnêtement si un contrôle ciblé suffit.
- Maillage entrant : `prix-referencement-naturel` depuis le passage sur le contenu d’un audit.
- Maillage sortant : prix SEO, refonte SEO, choix d’agence, service référencement Google.
- Aucun téléchargement, score gratuit ou résultat n’est promis.
